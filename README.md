# سایبو — مشاور خرید هوشمند (SYBO Beauty Advisor)

سایبو یک ابزار وب استاتیک (بدون بک‌اند، بدون دیتابیس، بدون API) برای فروشگاه‌های آنلاین لوازم آرایشی و بهداشتی است.
کاربر به‌جای مرور دستی ده‌ها محصول، در یک رابط شبیه چت‌بات به چند سؤال گزینه‌ای پاسخ می‌دهد و در پایان،
مناسب‌ترین محصولات فروشگاه بر اساس یک **موتور امتیازدهی قانون‌محور (بدون هوش مصنوعی)** به او پیشنهاد می‌شود.

- ۱۰۰٪ HTML / CSS / JavaScript خالص — بدون فریم‌ورک، بدون Node.js، بدون سرویس پولی
- بدون نیاز به نصب یا build؛ با باز کردن مستقیم `index.html` هم کار می‌کند
- کاملاً فارسی و راست‌چین (`lang="fa"` و `dir="rtl"`)
- طراحی Mobile First و کاملاً ریسپانسیو
- قابل انتشار روی GitHub Pages یا هر هاست استاتیک دیگر

---

## ۱. اجرای پروژه

### روش ۱ — باز کردن مستقیم فایل (ساده‌ترین راه)

فقط روی `index.html` دابل‌کلیک کنید. چون داده‌ها در `products.js`/`config.js` (نه JSON خارجی) نگه‌داری می‌شوند،
پروژه بدون نیاز به سرور محلی و بدون خطای CORS در مرورگر مستقیماً اجرا می‌شود.

### روش ۲ — با یک سرور محلی ساده (اختیاری، برای توسعه)

```bash
# با پایتون
python3 -m http.server 8080
# سپس در مرورگر باز کنید:
http://localhost:8080
```

## ۲. انتشار روی GitHub Pages

1. محتوای این پوشه را در یک ریپازیتوری گیت‌هاب push کنید (`index.html` باید در ریشه ریپو یا ریشه شاخه انتخابی باشد).
2. در تنظیمات ریپو، به بخش **Settings → Pages** بروید.
3. Source را روی شاخه‌ی موردنظر (مثلاً `main`) و پوشه‌ی `/ (root)` تنظیم کنید.
4. بعد از چند دقیقه، پروژه روی آدرسی شبیه `https://USERNAME.GITHUB.io/REPO-NAME/` در دسترس است.

> همه مسیرهای فایل در پروژه نسبی (relative) هستند (مثل `assets/js/app.js`)، پس این پروژه هم در ریشه دامنه
> و هم داخل یک زیرپوشه (مثل `/advisor/`) بدون تغییر کار می‌کند.

## ۳. قرار دادن پروژه داخل سایت اصلی

### روش ۱ — iframe (پیشنهادی، ساده‌ترین و بدون تداخل CSS/JS)

پروژه را روی GitHub Pages یا هر هاست استاتیک منتشر کنید و در صفحه‌ی موردنظر سایت اصلی این کد را قرار دهید:

```html
<iframe
  src="https://USERNAME.github.io/sybo-beauty-advisor/"
  title="مشاور خرید سایبو"
  style="width:100%; max-width:640px; height:720px; border:none; border-radius:16px; margin:0 auto; display:block;"
  loading="lazy">
</iframe>
```

ارتفاع (`height`) را بسته به نیاز خودتان تنظیم کنید؛ چون تعداد پیام‌های چت متغیر است، می‌توانید یک اسکرول داخلی
(که پروژه به‌صورت پیش‌فرض دارد) نگه دارید یا بعداً ارتفاع پویا با `postMessage` اضافه کنید (خارج از محدوده نسخه اول).

### روش ۲ — کپی مستقیم فایل‌ها در یک زیرپوشه

کل پوشه‌ی پروژه را در مسیری مثل `yoursite.com/advisor/` آپلود کنید و از سایت اصلی یک دکمه یا لینک به آن بدهید.
چون هیچ وابستگی بیرونی (جز فونت وب اختیاری) وجود ندارد، هیچ تداخلی با کد سایت اصلی رخ نمی‌دهد.

## ۵. مدل داده محصول

هر محصول در `assets/js/products.js` یک شیء با فیلدهای زیر است:

| فیلد | نوع | توضیح |
|---|---|---|
| `id` | string | شناسه یکتا |
| `name` | string | نام محصول |
| `brand` | string | برند |
| `category` | string | یکی از `sunscreen` \| `cleanser` \| `moisturizer` \| `shampoo` |
| `image` | string | مسیر تصویر (نسبی) |
| `shortDescription` | string | توضیح کوتاه (زیر نام محصول در کارت) |
| `fullDescription` | string | توضیح کامل‌تر (برای توسعه‌های بعدی مثل صفحه محصول) |
| `price` | number | قیمت به تومان (یا واحد تعریف‌شده در `config.js`) |
| `priceLevel` | string | یکی از `economy` \| `mid` \| `premium` \| `luxury` |
| `skinTypes` | string[] | برای دسته‌های پوستی: `oily`\|`dry`\|`combination`\|`normal`\|`sensitive`\|`all` |
| `hairTypes` | string[] | فقط شامپو: `oily`\|`dry`\|`normal`\|`sensitive`\|`color-treated`\|`damaged`\|`all` |
| `concerns` | string[] | نیاز اصلی که محصول پاسخ می‌دهد (به سؤال «نیاز اصلی/خشکی/حساسیت» مرتبط) |
| `texture` | string | بافت محصول (مقادیر مجاز در `recommendation-engine.js` مستندسازی شده) |
| `colorType` | string | فقط ضدآفتاب: `tinted` \| `untinted` |
| `preference` | string[] | فقط شامپو: `economical`\|`sulfate-free`\|`specialized` |
| `tags` | string[] | برچسب نمایشی (زیر توضیح، در کارت محصول) |
| `productUrl` | string | لینک صفحه محصول در فروشگاه |
| `orderUrl` | string | (رزرو شده برای توسعه بعدی؛ در حال حاضر سفارش از طریق واتساپ انجام می‌شود) |
| `available` | boolean | اگر `false` باشد، محصول هرگز پیشنهاد داده نمی‌شود |
| `featured` | boolean | اگر `true` باشد، ۱ امتیاز پاداش می‌گیرد (محصول ویژه فروشگاه) |

داده فعلی شامل **۲۰ محصول کاملاً فرضی** (۵ محصول در هر یک از ۴ دسته) برای تست موتور پیشنهاد است.
**قبل از استفاده واقعی، حتماً این داده‌ها را با محصولات واقعی فروشگاه جایگزین کنید** (بخش ۷).

## ۶. منطق امتیازدهی

هر دسته ۴ سؤال دارد. هر سؤال به یک معیار امتیازدهی نگاشت می‌شود (حداکثر ۱۴ امتیاز):

| معیار | امتیاز | توضیح |
|---|---|---|
| تطابق نوع پوست/مو | ۴ | **اجباری**؛ اگر صفر شود، محصول از لیست حذف می‌شود |
| تطابق با نیاز اصلی (یا رنگی/بی‌رنگ برای ضدآفتاب) | ۴ | |
| تطابق بافت (یا ترجیح محصول برای شامپو) | ۲ | |
| تطابق بودجه | ۳ | تطابق کامل = ۳، یک پله فاصله = ۱، بیشتر = ۰ |
| محصول ویژه فروشگاه (`featured`) | ۱ | پاداش ثابت |

اگر کاربر گزینه «تفاوتی ندارد» یا مشابه آن را انتخاب کند، آن معیار امتیاز کامل به همه محصولات می‌دهد
(چون کاربر ترجیح خاصی ندارد). اگر کاربر بودجه «محدودیت ندارم» را انتخاب کند، معیار بودجه هم امتیاز کامل می‌گیرد.

### چرا سؤال «رنگی/بی‌رنگ» برای ضدآفتاب معیار ۴ امتیازی است؟

در فهرست سؤال‌های ضدآفتاب، برخلاف بقیه دسته‌ها، سؤال جداگانه‌ای برای «نیاز اصلی» وجود ندارد. چون رنگی/بی‌رنگ‌بودن
برای اکثر کاربران یک الزام سخت است (نه یک ترجیح جزئی مثل بافت)، این معیار به‌جای «بافت» وزن ۴ امتیازی گرفته و
«بافت» وزن ۲ امتیازی شده است.

### انتخاب سه پیشنهاد نهایی

۱. **بهترین پیشنهاد**: محصول با بالاترین امتیاز.
۲. **گزینه اقتصادی‌تر**: ارزان‌ترین محصول باقی‌مانده (در میان محصولاتی که حداقل یک امتیاز دارند)، فقط اگر واقعاً ارزان‌تر از «بهترین پیشنهاد» باشد.
۳. **پیشنهاد جایگزین**: بالاترین امتیاز باقی‌مانده بعد از دو مورد قبلی.

اگر تعداد محصولات واجد شرایط کمتر از ۳ باشد، همان تعداد موجود نمایش داده می‌شود. اگر هیچ محصولی حداقل
در معیار نوع پوست/مو مطابقت نداشته باشد، پیام «محصولی با تطابق کامل پیدا نشد» + دکمه مشاوره واتساپ نمایش داده می‌شود.

منطق کامل در `assets/js/recommendation-engine.js` است و مستقل از رابط کاربری نوشته شده تا به‌سادگی
قابل تست واحد (unit test) یا توسعه (مثلاً افزودن معیارهای جدید) باشد.

## ۷. شخصی‌سازی برای یک فروشگاه جدید (گام‌به‌گام)

۱. **تنظیمات فروشگاه** — فایل `assets/js/config.js` را باز کنید و مقادیر زیر را ویرایش کنید:
   - `storeName`, `systemName`, `systemTagline`
   - `whatsappNumber` (فقط عدد، با کد کشور، بدون `+`)
   - `instagramUrl`
   - `primaryColor`, `secondaryColor` (این دو مقدار جنبه مرجع دارند؛ رنگ واقعی در `style.css` هم باید هماهنگ شود — گام ۴)
   - `logo`, `welcomeMessage`, `currency`, `disclaimerText`

۲. **لوگو** — فایل لوگوی خودتان را در `assets/images/logo/` قرار دهید و مسیر آن را در `config.js` (فیلد `logo`) به‌روزرسانی کنید.

۳. **محصولات** — یکی از دو روش را انتخاب کنید:
   - **ویرایش مستقیم**: آرایه `PRODUCTS` در `assets/js/products.js` را با محصولات واقعی جایگزین کنید (به بخش ۵ برای فیلدها نگاه کنید).
   - **از روی CSV**: فایل `docs/product-data-template.csv` را با اکسل/Google Sheets پر کنید (توضیح فرمت در بخش ۸)، سپس محتوای هر
     سطر را به یک شیء در `products.js` تبدیل کنید. (چون پروژه بدون بک‌اند است، تبدیل CSV به JS باید یک‌بار و دستی یا با
     یک اسکریپت کمکی خارج از مرورگر انجام شود؛ فایل CSV صرفاً برای جمع‌آوری منظم اطلاعات از مشتری است.)

۴. **رنگ برند** — در `assets/css/style.css`، بخش `:root` را باز کنید و مقادیر زیر را با رنگ برند خودتان هماهنگ کنید:
   ```css
   --color-primary: #2F6F63;
   --color-primary-dark: #235248;
   --color-primary-light: #e6f0ee;
   --color-secondary: #C9A55C;
   --color-secondary-light: #f7efdf;
   ```

۵. **دسته‌بندی‌های بیشتر (اختیاری)** — برای افزودن دسته جدید (مثل سرم، تونر، ماسک مو):
   - در `assets/js/app.js`، داخل شیء `CATEGORY_FLOWS` یک دسته جدید با ۴ سؤال تعریف کنید و آن را به آرایه `CATEGORY_MENU` اضافه کنید.
   - در `assets/js/recommendation-engine.js`، داخل `CATEGORY_SCORERS` یک تابع امتیازدهی متناظر با کلید همان دسته اضافه کنید
     (می‌توانید از الگوی دسته‌های موجود کپی کنید).
   - محصولات آن دسته را با `category: "your-new-category"` به `products.js` اضافه کنید.

۶. **تصاویر محصولات** — تصاویر را در `assets/images/products/` قرار دهید و مسیر آن‌ها را در فیلد `image` هر محصول ثبت کنید.
   اگر تصویری موجود نباشد یا لود نشود، به‌صورت خودکار `assets/images/placeholder.webp` جایگزین می‌شود.

## ۸. فرمت فایل CSV (`docs/product-data-template.csv`)

ستون‌ها:

```
id, name, brand, category, image, shortDescription, price, priceLevel,
skinTypes, hairTypes, concerns, texture, colorType, tags, productUrl, available
```

- مقادیر چندتایی مثل `skinTypes`، `hairTypes`، `concerns` و `tags` با علامت `|` از هم جدا می‌شوند. مثال:

  ```
  oily|combination|acne-prone
  ```

- `category` باید دقیقاً یکی از `sunscreen`, `cleanser`, `moisturizer`, `shampoo` (یا شناسه دسته جدیدی که تعریف کرده‌اید) باشد.
- `priceLevel` باید یکی از `economy`, `mid`, `premium`, `luxury` باشد.
- `available` باید `true` یا `false` باشد.
- ستون‌هایی که برای یک دسته کاربرد ندارند (مثلاً `hairTypes` برای ضدآفتاب) می‌توانند خالی بمانند.

## ۹. سناریوهای تست پیشنهادی

قبل از انتشار نهایی، این سناریوها را دستی امتحان کنید:

- پوست چرب، ضدآفتاب بی‌رنگ، بودجه اقتصادی

- یک تصویر محصول را عمداً خراب کنید (مسیر اشتباه) و مطمئن شوید placeholder جایگزین می‌شود
- اجرا روی موبایل (ابعاد کوچک) و دسکتاپ
- باز کردن مستقیم `index.html` (بدون سرور محلی)
- اجرا روی GitHub Pages بعد از انتشار

## ۱۰. ملاحظات فنی، امنیتی و محدودیت‌ها

- **بدون ذخیره داده حساس**: تنها چیزی که (به‌صورت اختیاری) در `localStorage` ذخیره می‌شود، پاسخ‌های همان جلسه گفتگو
  (`sybo_session_v1`) است تا در صورت رفرش تصادفی صفحه از دست نرود؛ بعد از دیدن نتیجه یا شروع مجدد پاک می‌شود. هیچ
  اطلاعات شخصی کاربر جمع‌آوری نمی‌شود.
- **جلوگیری از XSS**: تمام متن‌های پویا (نام محصول، توضیحات) با `textContent` (نه `innerHTML`) درج می‌شوند تا در صورت
  ورود کاراکترهای خاص در داده محصولات، کد HTML/JS ناخواسته اجرا نشود.
- **این ابزار تشخیص پزشکی نمی‌دهد**: طبق نیاز پروژه، زیر نتایج همیشه هشدار حرفه‌ای نمایش داده می‌شود و هیچ ادعای
  درمانی یا تشخیصی در متن‌ها وجود ندارد.
- **دسترس‌پذیری پایه**: تمام گزینه‌ها `<button>` واقعی هستند (قابل دسترسی با کیبورد/Tab)، ناحیه چت `aria-live="polite"`
  دارد تا صفحه‌خوان‌ها پیام جدید را اعلام کنند، و `:focus-visible` برای فوکوس واضح تعریف شده است.
- **فونت وب**: فونت وزیرمتن از Google Fonts CDN بارگذاری می‌شود (تنها وابستگی بیرونی پروژه). اگر می‌خواهید پروژه
  کاملاً آفلاین/بدون اینترنت هم کار کند، فایل فونت را دانلود و به‌صورت local در `assets/fonts/` قرار دهید و
  `index.html` را به آن ارجاع دهید؛ در غیر این صورت مرورگر به فونت‌های پیش‌فرض سیستم (Segoe UI/Tahoma) برمی‌گردد و
  ظاهر همچنان قابل‌قبول می‌ماند.
- **مقیاس داده**: چون همه محصولات در یک فایل JS بارگذاری می‌شوند، این معماری برای چند صد محصول کاملاً مناسب است؛
  برای کاتالوگ‌های بسیار بزرگ (چند هزار محصول)، در آینده باید به سمت واکشی داده (fetch) یا بک‌اند حرکت کرد که
  خارج از محدوده نسخه اول است.

## ۱۱. سلب مسئولیت

پیشنهادهای این ابزار صرفاً بر اساس اطلاعات محصولات و پاسخ‌های کاربر ارائه می‌شوند و جایگزین مشاوره پزشک یا
متخصص پوست و مو نیستند. این ابزار هیچ بیماری تشخیص نمی‌دهد، ادعای درمان ندارد و تضمین پزشکی ارائه نمی‌کند.
